# VHF wheel feasibility driver

`VhfWheelTest` is an isolated, root-enumerated KMDF client of Windows Virtual
HID Framework (VHF). It does not enumerate, open, filter, or bind to a physical
Magic Mouse or any other physical device. Its virtual HID report contains:

- a conventional zero-motion mouse layout with three unpressed buttons and
  relative X/Y fields held at zero,
- relative Generic Desktop `Wheel` (vertical), and
- relative Consumer `AC Pan` (horizontal).

The package registers the system `vhf.sys` driver as a lower filter for only
the root-enumerated test device.

The device interface is restricted to LocalSystem and local administrators.
The only IOCTL requires write access, an exact versioned request structure, a
zero reserved field, signed deltas in `-127..127`, and at least one non-zero
delta. The client additionally bounds a run to 1,000 reports and 0..1,000 ms
between reports.

## Prerequisites

- A disposable or controlled x64 Windows 10/11 development machine or VM.
- Visual Studio 2026 with the Desktop development with C++ workload.
- Network access to `nuget.org` during restore.
- Administrator PowerShell for install/uninstall.
- A test-signing certificate and signing procedure managed outside this
  repository. No certificate or private key is generated or stored here.

Do not use a production machine. Create a VM checkpoint before installation.
These instructions never enable test-signing automatically.

## Build

The driver pins the stable `Microsoft.Windows.WDK.x64` package
`10.0.28000.2526` and its `Microsoft.Windows.SDK.CPP.x64` dependency
`10.0.28000.2526`. Packages use NuGet's normal per-user cache; no WDK or SDK
component is installed machine-wide and no package content is committed.

From the repository root, use the Visual Studio 2026 MSBuild executable. The
`/restore` switch makes the command reproducible on a clean checkout:

```powershell
& 'C:\Program Files\Microsoft Visual Studio\18\Community\MSBuild\Current\Bin\MSBuild.exe' .\driver\VhfWheelTest\VhfWheelTest.vcxproj /t:Rebuild /restore /m /p:Configuration=Debug /p:Platform=x64
& 'C:\Program Files\Microsoft Visual Studio\18\Community\MSBuild\Current\Bin\MSBuild.exe' .\tools\VhfWheelClient\VhfWheelClient.vcxproj /m /p:Configuration=Debug /p:Platform=x64
```

Adjust only the Visual Studio edition segment if Visual Studio 2026 is
installed as Professional or Enterprise. Do not use `dotnet restore`; Microsoft
does not support the `dotnet` command for WDK NuGet projects.

The NuGet package's in-process package verifier currently looks for an x86
`InfVerif.dll` that is not present in the x64 package, so the project disables
that one target and still runs `Inf2Cat` during the build. Validate the emitted
INF directly with the restored x64 verifier:

```powershell
& "$env:USERPROFILE\.nuget\packages\microsoft.windows.wdk.x64\10.0.28000.2526\c\tools\10.0.28000.0\x64\InfVerif.exe" /w /v .\driver\VhfWheelTest\x64\Debug\VhfWheelTest\VhfWheelTest.inf
```

The driver package is emitted under
`driver\VhfWheelTest\x64\Debug\VhfWheelTest\`; the client is emitted under
`tools\VhfWheelClient\x64\Debug\`.

## Test-signing

Sign the generated `.sys` and `.cat` using your organization's existing
test-signing process and certificate. If a catalog was not generated by the
build, create one with the WDK `Inf2Cat` tool before signing. Import only the
public certificate into the test machine's required trust stores.

If the controlled machine is not already configured to load test-signed
drivers, follow Microsoft's current test-signing documentation and your
organization's policy, then reboot. This project deliberately does not run
`bcdedit`, create certificates, install certificates, or alter boot policy.
Secure Boot may prevent test-signing configuration.

## Install

In an elevated PowerShell, from the repository root, use the built and signed
INF:

```powershell
pnputil /add-driver .\driver\VhfWheelTest\x64\Debug\VhfWheelTest\VhfWheelTest.inf /install
devcon install .\driver\VhfWheelTest\x64\Debug\VhfWheelTest\VhfWheelTest.inf Root\VhfWheelTest
```

`devcon.exe` is supplied by the WDK. The explicit `Root\VhfWheelTest` hardware
ID creates the manual test device; the INF cannot match physical mouse
hardware. In Device Manager, verify **Synthetic VHF Wheel Test Device** appears
under **System devices**, and a new HID-compliant virtual device appears.

## Run

Run the client elevated because the device interface permits only
administrators and LocalSystem:

```powershell
.\tools\VhfWheelClient\x64\Debug\VhfWheelClient.exe 1 0 10 100
.\tools\VhfWheelClient\x64\Debug\VhfWheelClient.exe 0 -1 10 100
```

Arguments are vertical delta, horizontal delta, optional report count, and
optional interval in milliseconds. Limits are printed by `--help` or on an
invalid invocation. Test only in a benign application where scrolling is safe.

## Uninstall

In elevated PowerShell:

```powershell
devcon remove Root\VhfWheelTest
pnputil /enum-drivers
pnputil /delete-driver oemNN.inf /uninstall
```

Replace `oemNN.inf` with the published name whose original name is
`VhfWheelTest.inf`. Reboot if Windows reports that removal is pending.

## Rollback

1. Stop using the client.
2. Remove the root device and driver package using the uninstall commands.
3. Reboot and verify both the System device and its virtual HID child are gone.
4. If this VM was configured for test-signing solely for this experiment,
   restore the pre-test VM checkpoint or manually restore boot policy according
   to your organization's procedure. Do not remove shared certificates or
   change boot policy unless you know they were introduced for this test.
